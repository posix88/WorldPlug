# Socket Buddy — Codebase Guide for AI Agents

Read this before touching the code. It describes what actually exists today, not the aspirational state. Where this file and `.github/copilot-instructions.md` / `.github/instructions/*.md` disagree, **this file wins** — the `.github` docs describe an earlier project layout (pre-reorg, iOS 17) and are stale in places (see "Known doc drift" below). They're still useful for the *conventions* (naming, MVVM shape, testing style), just not for the current folder layout or deployment target.

## What this app is

**Socket Buddy** (Xcode project still named `WorldPlug`, bundle id `com.posix88.Voltly`) is a personal iOS app that tells travelers everything about electrical plugs, sockets, voltage and frequency for 200+ countries, checks whether their devices are safe to use abroad, and lets them save countries/trips behind a one-time $4.99 IAP ("Socket Buddy Premium"). It ships a WidgetKit extension, Siri/Spotlight App Intents, iCloud-synced preferences, and on-device AI (Vision + Apple FoundationModels) for reading device labels via the camera.

**Naming**: the App Store / marketing name is "Socket Buddy" — "Voltly" (the original working name) turned out to already be taken. Every internal identifier still says "Voltly" on purpose (Apple only checks the App Store listing name for uniqueness, not any of these): the bundle ID (`com.posix88.Voltly`), the App Group (`group.com.posix88.Voltly`), the URL scheme (`voltly://`), the Xcode project name (`WorldPlug`), the Firebase project (`voltly-1527f`), and every `Voltly*`-prefixed Swift type (`VoltlyApp`, `VoltlyWidgets`, `VoltlyDeepLink`, `VoltlyAppShortcuts`, …). Only user-visible text was changed: `CFBundleDisplayName`, the onboarding/paywall/share-sheet copy, the camera permission string, the widget empty-state text, and the App Store metadata in `fastlane/metadata/`. Don't "fix" the internal naming without a good reason — it's intentionally left alone, not an oversight.

- Target: iOS 27.0+ (`IPHONEOS_DEPLOYMENT_TARGET = 27.0`), universal (iPhone + iPad), Swift 6.0, **strict concurrency = complete**.
- No `SWIFT_DEFAULT_ACTOR_ISOLATION` override — every `@MainActor` is explicit, by convention. Follow that convention; don't rely on default-MainActor-isolation behavior.
- State: `@Observable` everywhere (never `ObservableObject`/`@Published`).
- Persistence: SwiftData, isolated inside the `Repository` Swift package.
- Testing: Swift Testing (`@Test`/`#expect`), never XCTest.
- Formatting: SwiftFormat via `.swiftformat` at repo root; install the pre-commit hook with `git config core.hooksPath './hooks'` (see [README.md](README.md)).

## Module map

| Module | Type | Owns |
|---|---|---|
| `WorldPlug/` | App target | SwiftUI app, all features, App Intents, analytics wiring |
| `Repository/` | SwiftPM package | SwiftData `@Model`s (`Country`, `Plug`), JSON-seeded catalog data, `CountrySnapshot` (Sendable read model for widgets), `AppGroup` (shared UserDefaults keys/suite) |
| `Analytics/` | SwiftPM package | `AnalyticsTracker` protocol + Firebase Analytics implementation |
| `VoltlyWidgets/` | Widget extension | Home Country, Favorite Country, Next Trip widgets (all families) |
| `Tools/Formatter/` | SwiftPM package | Vendored SwiftFormat CLI used by the pre-commit hook |
| `WorldPlugTests/`, `Repository/Tests/`, `Analytics/Tests/` | Test targets | Swift Testing suites |

**Rule inherited from the old docs and still true**: `@Model` types live only in `Repository`. The app and widget targets never define SwiftData models directly — they read through `Repository.sharedModelContainer` (app) or `CountrySnapshotRepository`/App Group `UserDefaults` (widgets, since widgets run in a separate process and SwiftData model objects aren't `Sendable` across it).

## Core architecture facts an agent needs before editing

- **Navigation**: single `AppNavigationModel.shared` singleton (`@Observable @MainActor`) drives tab selection + deep-linked country code. `AppCoordinator` (also `@MainActor`, owned by `VoltlyApp`) is the app-level state machine: launch splash → onboarding (if first run) → premium paywall presentation → deep link routing. `VoltlyDeepLink` parses `voltly://country/<code>` and `voltly://premium` URLs; widget deep links must match this exactly or tapping the widget silently no-ops.
- **Premium gating**: single source of truth is `StoreKitPremiumEntitlement.isPremium` (`@Observable @MainActor`, StoreKit 2, one non-consumable product `com.posix88.voltly.premium`). It's injected via `@Environment(\.premiumEntitlement)`. `AppCoordinator.syncPremiumWidgetAccess()` mirrors `isPremium` into the App Group `UserDefaults` key `AppGroup.premiumAccessKey` and calls `WidgetCenter.shared.reloadAllTimelines()` — **this is the only bridge between the main app's entitlement and what widgets can show**; if you rename/move that key on one side without the other, widget premium-gating silently breaks.
- **App Group contract** (`Repository/Sources/AppGroup.swift`, suite `group.com.posix88.Voltly`): home country code, favorite country code, next-trip country/departure/return dates, premium flag. The `nextTrip*` keys are still named that way and still hold exactly one trip, but which trip that is is now **derived** by `TravelPreferences.currentTrip()` rather than chosen by the user — see the "one Trip" bullet below. Widgets read these directly via `UserDefaults(suiteName:)` and resolve country data through `CountrySnapshotRepository` (a lightweight, `Sendable` read path — not the full SwiftData stack). If you add a new cross-process value, add the key here, write it from the app, and read it identically from every widget provider that needs it.
- **SwiftData schema**: **deliberately unversioned.** There is no `VersionedSchema`, no `SchemaMigrationPlan`, and no `Schema.swift` — `Country` and `Plug` are plain top-level `@Model` classes in `Repository/Sources/{Country,Plug}.swift`. The app has never shipped, and this container holds only a read-only catalog reseeded from bundled JSON by `preloadData()`, so the correct response to any model change is to throw the store away and reseed. `Repository.sharedModelContainer` does exactly that: on any container error it logs (`logger.fault`, no `assertionFailure` — hitting this path is expected whenever the model layout changes, not a programmer error), deletes the default store plus its `-wal`/`-shm` sidecars, and retries once before `fatalError`-ing. **Do not add versioning back** unless this container starts holding data that can't be regenerated from JSON.
- **iCloud sync**: `ICloudTravelPreferencesStore` wraps `NSUbiquitousKeyValueStore` and observes `didChangeExternallyNotification` (in addition to reloading on foreground: `AppCoordinator.sceneBecameActive()` → `HomeCountryViewModel.refreshHomeCountry()` → `reloadFromICloud()`), so changes made on another device show up live, not just on foreground. `reloadFromICloud()` deliberately re-mirrors the widget values **even when nothing changed** — the widgets' trip is derived from today's date, so it goes stale through the passage of time alone.
- **One Trip, and the widget's trip is derived**: there is a single trip concept, `Trip` (destination + departure/return dates + optional name + `[PackDevice]`), stored in `TravelPreferences.trips`. The old `NextTrip` type is gone — it was a strict subset of `TripCheck` (same four fields, minus devices), and having both meant "add a trip" existed in two tabs with no relation between them. `TravelPreferences.currentTrip(now:calendar:)` picks the one trip the widgets and Siri talk about: an in-progress trip wins (today falls within departure...return inclusive, compared by whole days), otherwise the soonest future departure, otherwise `nil`. Trips that have ended are never picked, but they are **kept** — shown dimmed in the list, and `Trip.isPast()` excludes them from the free-tier trip limit. Nothing deletes a trip behind the user's back any more (the old `removingExpiredTrip` did, on every load).
- **Trips flow (three screens, one job each)**: `TripsView` lists trips in an **Upcoming** section (ongoing + future, soonest first) and a **Past** section (most recent first, dimmed), badging the derived `currentTrip()` with "Next" so the widget's choice is visible in-app. `TripEditorView` creates *and* edits the trip itself — destination, dates, name, nothing else; it has no premium dependency. `TripDetailView` owns the devices: it's where `PackDeviceEditorView` and the label scanner are pushed from, where the free-device limit and paywall live, and where each device's verdict is shown. **`TripDetailViewModel` is the writer** — it calls `saveTrip` on every device add/remove, because the create-then-add-devices flow has no later "save the whole trip" moment the way the old single creation sheet did. When the editor sheet hands a trip back to `TripDetailViewModel.saveTrip(_:)`, the devices this screen holds are re-attached — the editor doesn't own them and returns them empty.
- **Trip safety logic**: `DeviceSafetyAssessment` + `VoltageCompatibility`/`FrequencyCompatibility` (`Models/Home Country/HomeCountryViewModelType.swift`) decide whether a packed device is `.ready` / `.adapterNeeded` / `.checkLabel` / unsafe for a destination. This is the one piece of business logic with real-world physical-safety consequences (wrong verdict ⇒ user could plug an incompatible device into a wall socket). Read the "Known issues" section before changing tolerances or the label-parsing regexes.
- **Analytics**: `AnalyticsTracker` protocol (`Analytics` package) with a Firebase-backed implementation and `NoopAnalyticsTracker` for previews/tests, injected via `@Environment(\.analyticsTracker)`. `AppDelegate` calls `FirebaseAnalyticsTracker.configure()` in `didFinishLaunchingWithOptions`.
- **Camera usage**: `DeviceLabelScannerView` uses `VisionKit.DataScannerViewController` (not raw `AVCaptureSession`). `NSCameraUsageDescription` **is** correctly set in `en.lproj`/`it.lproj` `InfoPlist.strings` (EN: "Socket Buddy uses the camera to read the voltage and frequency printed on your device label.").

## Localization

- String catalogs live in `WorldPlug/Resources/Copies/`: `Localizable.xcstrings` (220 keys, source language English), `Accessibility.xcstrings`, `AppShortcuts.xcstrings`.
- Two shipping languages: **English** and **Italian**, both essentially fully localized (only interpolation-format placeholder keys like `"%@"` and the brand name `"Socket Buddy"` are identical in both locales, which is correct — a brand name doesn't get translated).
- Access strings through the `LocalizationKeys` enum (`UI Components/Localizable.swift`), not raw string literals — `String(localized: LocalizationKeys.xxx)`.
- `InfoPlist.strings` per-locale (camera usage description, etc.) live in `WorldPlug/Resources/{en,it}.lproj/`.
- `VoltlyWidgets/Sources/WidgetLocalization.swift` handles widget-extension-side localization separately (it can't share the app target's string catalog directly).

## Known issues (from the 2026-08 correctness/concurrency pass)

All findings from the original review have been fixed as of 2026-08-19, across three passes (5 launch-blocking, 6 "worth a look", then the remaining open items). Full build + full test suite (app target on Xcode 27 beta 4 / iOS 27 SDK, arm64 simulator, and the `Repository` SwiftPM package via `swift test`) pass cleanly and repeatably — verified with three consecutive full runs, no flakes. The generic/x86_64 simulator destination still fails to build regardless of any of this — `FoundationModels` isn't available on that slice, a pre-existing environment limitation, not a regression.

**Launch-blocking (fixed):**
1. Onboarding covering the launch splash for first-time users (`AppCoordinator.isOnboardingPresented` now only flips true from `launchExperienceCompleted()`).
2. Missing `NSUbiquitousKeyValueStore.didChangeExternallyNotification` observer in `ICloudTravelPreferencesStore` (now observes live, with a `preferences != oldValue` guard to avoid write-echo).
3. TripCheck safety logic failing open on unparseable voltage/frequency, flat ±20V tolerance, and a label-parsing regex that missed `"AC100-240V"`-style labels (`VoltageCompatibility`/`FrequencyCompatibility`/`DeviceLabelParser`).
4. `Repository.cleanDataBase()` never calling `save()`.
5. Next Trip widget routing already-premium users to the paywall when they simply had no active trip.

**Worth a look (fixed):**
6. Device label scanner double-tap race (`DeviceLabelScannerView` now gates re-entrancy, marks `.analyzing` before the camera capture, and cancels stale tasks).
7. `scannedValues`' `Equatable`-gated `onChange` silently missing a second identical device scan (`PackDeviceEditorView` now resets it to `nil` after consuming it).
8. `CountryMapGeocoder` having no fallback for an inexact MapKit match and no negative-result caching (`bestMapItem` now falls back to the first result; failed lookups are cached in `codesWithoutAFocus` for the session).
9. SwiftData migration plan only covering V4→V5 with a hard `fatalError` on any container error (`Repository.sharedModelContainer` now discards an unopenable store and retries once, since the catalog is fully reseedable).
10. `WidgetPlugs.swift` hardcoding an unlocalized `"Type \(plugType)"` (now uses `WidgetStrings.string("widget.plug.type", plugType)`).
11. StoreKit `.pending` purchases giving no user feedback (`PremiumPaywallViewModel.isPurchasePending` + a dedicated "Purchase pending" alert, new EN/IT keys).

**Remaining findings from the full review (fixed):**
12. Redundant full Spotlight reindex on every cold launch — `CountrySpotlightIndex.indexAllCountries()` now only reindexes when `CFBundleShortVersionString` has changed since the last successful index (stamped in `UserDefaults`).
13. `OpenHomeCountryIntent` reading only the App Group suite instead of reusing `UserDefaultsHomeCountryStore`'s App-Group-with-standard-defaults fallback — now reuses it, matching the rest of the app.
14. `preloadData()`/container-recovery failures only ever `print`ed — `Repository` now has an `os.Logger` (`com.posix88.Voltly.Repository`) so failures show up in Console/Xcode's log views instead of being easy to miss.
15. Launch splash dismissing on a fixed timer independent of `premiumEntitlement.refreshEntitlements()` completing — `AppCoordinator.hasRefreshedEntitlements` + `LaunchExperienceView(isReady:)` now gate dismissal on both the minimum splash duration *and* entitlement refresh finishing (with a ~3s total safety-net timeout so a slow/hung refresh can never block the splash indefinitely).
16. `CountryMapGeocoder` geocoding taking a fixed 2s delay before animating regardless of network speed, and no "couldn't locate" state distinct from "still locating" — added `CountryMapLoadState` (`.locating`/`.located`/`.unavailable`) to `CountryDetailViewModel`, surfaced as a small pill (`country.detail.map.unavailable`, new EN/IT keys) over the map when geocoding genuinely fails. The 2s delay itself was left as-is — it's a deliberate "let the globe settle, then fly in" animation beat, not a bug.
17. `CountriesListViewModel.fetchData()` silently leaving the catalog empty on a fetch error in release builds (`assertionFailure` is a no-op there) — now also tracks a new `.catalogFetchFailed` analytics event with the error description.
18. `NextTripEditorViewModel`'s "return date can't precede departure" invariant only being enforced reactively via `departureDateChanged()`, not at construction — now also clamped in `init`.
19. Camera/photo-capture failures being silently swallowed with no telemetry (`try? scanner.startScanning()`, the FoundationModel-interpreter-throws-so-fall-back-to-Vision path) — both now tracked via new `.deviceLabelScanStartFailed`/`.deviceLabelSmartAnalysisFailed` analytics events; the graceful-degradation *behavior* is unchanged, only visibility was added.

**Two test issues found during verification, also fixed (not part of the original review, found while confirming the above didn't regress anything):**
- `CountriesListViewModelTests.refreshCompatibilitySummaries()` was failing deterministically on unmodified `main` too: its `japan`/`usa` fixtures had no plugs, so `CountryCompatibilityCalculator.summary(for:)` (which only derives a verdict from `country.sortedPlugs`) had nothing to iterate over and always returned `.compatible`. Fixed by giving the fixture countries a plug each, matching real catalog data (every real country has at least one).
- A `HomeCountryViewModelTests` test was failing intermittently (a different one each run), consistent with SwiftData in-memory `ModelConfiguration` containers colliding under Swift Testing's default parallel execution. Fixed by marking both `CountriesListViewModelTests` and `HomeCountryViewModelTests` `@Suite(..., .serialized)`.

**Nothing left open from this review.** If you're reading this after making more changes, add a new dated section here rather than editing history above — keep this list a log, not just a snapshot.

## 2026-09-10 — migration-code purge (Chunk 0 of the Saved/Trips restructure)

Nothing here has ever shipped to the App Store and the owner is the only user, so every migration and legacy-tolerance path was deleted rather than maintained. Subtraction only — no behaviour was added.

- **Deleted** `Repository/Sources/Schema.swift` (`SchemaV4`, `SchemaV5`, `MigrationPlan`, plus a commented-out `V2 → V3` stage) and `Repository/Sources/LegacySchemaV4.swift` (the V4 model snapshot). `Country`/`Plug` moved out of `extension SchemaV5 { … }` to top-level `@Model` classes; the `public typealias Plug = SchemaV5.Plug` pair and both `migrationPlan:` arguments are gone. `PlugType` was already top-level and didn't move.
- **Dropped the `assertionFailure`** from the container-recovery path in `Repository.sharedModelContainer`. Removing `VersionedSchema` changes the store's identity, so the recovery path (delete store → reseed) *is* the migration now and fires on the first launch after this change; trapping the debugger on a failure the code immediately recovers from was pure noise. `logger.fault` still records it.
- **`TravelPreferences`**: deleted the hand-written `init(from:)` + `CodingKeys` on both `TravelPreferences` and `TripCheck` (all those `decodeIfPresent` fallbacks existed only to read older blob shapes) — synthesized `Codable` now. Deleted the `TravelDevice` enum (a fossil referenced only from its own file), `PackDevice(legacyDevice:tripID:index:)`, the `legacyIdentifier` SHA256 UUID derivation, and `import CryptoKit`. The `tripCheckDevice*` localization keys stay — `DeviceIconOption` still uses them. An old iCloud blob now simply fails to decode, and `loadPreferences` already falls back to `TravelPreferences()`.
- **`UserDefaultsHomeCountryStore`**: deleted the `legacyDefaults` parameter, the dual write to standard defaults, the read fallback, and `migrateLegacyValueIfNeeded()`. It's App-Group-only now, with `.standard` kept solely for the case where the suite can't be opened at all. `HomeCountryViewModel.initialHomeCountryCode`'s third branch was *not* removed — it reconciles "iCloud empty but local store set" (not-yet-synced, or signed out), which is live resilience, not migration; its `legacyCountryCode` local was renamed `localCountryCode` to stop it reading like dead code.
- **Tests**: deleted `legacyDeviceIdentifiersAreStableAndDistinct`, `TravelPreferencesTests.decodesPreferencesStoredBeforeHomeCountrySync`, and replaced `UserDefaultsHomeCountryStoreTests.migratesLegacyValueIntoSharedDefaults` with a plain set/read/clear round-trip.

Verified: `swift build` + `swift test` in `Repository` (35 tests, 6 suites) and `xcodebuild build` + `test` for the app target on an iPhone 17 Pro simulator — all green. SwiftFormat clean (0/9 files changed).

## 2026-09-10 — one Trip concept (Chunk A of the Saved/Trips restructure)

`NextTrip` and `TripCheck` were the same shape (`countryCode`, `departureDate`, `returnDate`, `name`), the former just without devices — so "add a trip" existed independently in the Saved tab *and* the Pack Check tab, creating two unrelated records. Collapsed into one type.

- **`NextTrip` deleted.** `TripCheck` renamed `Trip`, `TravelPreferences.tripChecks` renamed `trips`. `TripCheckEntity`/`TripCheckEntityQuery` renamed `TripEntity`/`TripEntityQuery` — safe, because Shortcuts shows `typeDisplayRepresentation`, not the Swift type name (its key moved from `intent.trip.check.entity.type` to `intent.trip.entity.type`, default value "Trip"). View and view-model type names (`TripCheckView`, `TripCheckViewModel`, …), the `Features/TripCheck/` folder, `LocalizationKeys.tripCheck*`/`nextTrip*`, `beginTripCheck()` and the `tripCheck.*` accessibility identifiers are all **still on the old names** on purpose — Chunk B rewrites those files anyway, so renaming them here would have been churn on code about to change shape.
- **Added `TravelPreferences.currentTrip(now:calendar:)`** plus `Trip.contains(_:calendar:)` and `Trip.isPast(now:calendar:)`. See the "One Trip" bullet in the architecture section for the selection rule.
- **`removingExpiredTrip` deleted** (3 call sites). It silently destroyed the user's trip on load once the return date passed. Past trips are now kept.
- **`ICloudTravelPreferencesStore`**: `setNextTrip` gone from the protocol and all four conformances; `saveTripCheck`/`removeTripCheck` → `saveTrip`/`removeTrip`, and the create/update/remove analytics moved onto them (they were on `setNextTrip` before, so trip saves were previously untracked). `mirrorWidgetValues()` now feeds the App Group from `currentTrip()`. **The widget target has zero changes** — the App Group keys and their meaning are unchanged.
- **`reloadFromICloud()` now re-mirrors even when the blob is unchanged.** A derived trip can go stale through the passage of time alone, and the `preferences != oldValue` guard on `didSet` means an unchanged reload would otherwise skip the mirror entirely.
- **No default destination for a new trip.** `TripCheckEditorViewModel`'s prefill fell back to `countries.first`, i.e. it quietly proposed Andorra; and its other prefill source was `preferences.nextTrip`, which no longer exists. The initializer now takes only `premiumEntitlement` and starts with an empty `countryCode`, so `canSave` stays false until the user picks a destination on purpose.
- **Free-tier trip limit counts non-past trips only** (`trips.count(where: { !$0.isPast() })`), so an old trip can't lock a free user out of making a new one. Analytics `tripCheckLimitReached` → `tripLimitReached`, `nextTripCreated/Updated/Removed` → `tripCreated/Updated/Removed`, screens `.nextTrip`/`.nextTripDestination` → `.trips`/`.tripEditor`/`.tripDestination`.
- **Saved tab lost its trip UI** early (the toolbar button, the next-trip card, the editor sheet, `NextTripTip`, and `NextTripEditorView`/`NextTripEditorViewModel` are deleted) because deleting `NextTrip` forced it. Chunk C still owns the rest of that tab's slimming.
- **`AppDebugOverrides`** no longer seeds a `nextTrip` that duplicated its own first trip check, and gained a third, already-finished trip so the dimmed "past" treatment and the free-limit rule are both exercisable in debug.

Two notes for whoever picks up Chunk B: `TripCheckView`'s `body` had to be split (`listContent` + `tripRow(_:)`) because the type-checker gave up on it — the file is already at the edge of what it can infer, so keep new UI in small helpers. And `TripCheckViewModel.delete(at:)` indexes into the flat `trips` array, which will break the moment the list grows an Upcoming/Past section split.

Verified: `xcodebuild build` + `test` on an iPhone 17 Pro simulator — 129 tests pass, 0 failures. SwiftFormat clean (0/19 files changed).

## 2026-09-10 — Trips tab restructure (Chunk B of the Saved/Trips restructure)

The old flow made you fill in destination *and* at least one device in a single creation sheet before a trip could exist (`canSave` required `!devices.isEmpty`), and once created a trip could not be edited at all — tapping it went to a read-only result screen. Trips also had dates in the model that no UI ever showed. Split into three screens with one job each.

- **Folder and file renames**: `Features/TripCheck/` → `Features/Trips/`. `TripCheckViewModel`/`View` → `TripsViewModel`/`TripsView`, `TripCheckEditor*` → `TripEditor*`, `TripCheckResult*` → `TripDetail*`. `TripCheckRowModel` → `TripRowModel`, and `TripCheckEditorRoute` became `PackDeviceEditorRoute` (it now has a single case, `labelScanner`, and lives inside the device-editor sheet). `AppTab.tripCheck` → `.trips`, `PremiumPaywallSource.tripCheck` → `.trips` (raw value `trip_check` → `trips`). `CountryDestinationPickerView`/`ViewModel` moved out of `Features/SavedCountries/` to `UI Components/` — three screens use it now, so it isn't a Saved-tab detail any more.
- **`TripEditorView` is now just the trip**: destination, dates, name. Its dependency on `PremiumEntitlementProviding` is gone, along with `navigationPath`, the device list, the device-editor/scanner destinations and the paywall sheet — all of which moved to the detail screen. It serves creation *and* editing (`TripEditorViewModel(trip:)`), and shows a Remove trip button with a confirmation dialog when editing. `canSave` is now `destination set && returnDate >= departureDate`; requiring a device to exist before a trip could be saved was the thing that made the old flow feel backwards.
- **`TripDetailView` absorbed the result screen** and became the device surface: header (flag, name, date range, destination voltage/frequency), a device row per verdict with swipe-to-delete, an "Add device" row, an empty state when there are no devices yet, the retained safety disclaimer inset, and an Edit toolbar button that presents `TripEditorView`.
- **`TripDetailViewModel` is a writer, not a reader.** The screen it replaced held a value copy and computed `assessments` once in `init`; nothing it did was ever persisted, because the creation sheet's Save was the only write. Devices are now added incrementally with no later save moment, so every add/remove calls `travelPreferencesStore.saveTrip`, and `assessments` is a computed property that recomputes off the current devices. `screenAppeared` re-reads the trip from the store so edits made elsewhere (the editor sheet, or another device via iCloud) can't leave a stale copy on screen. `saveTrip(_:)` re-attaches the devices this screen holds, because the editor doesn't own them and hands back an empty list.
- **Upcoming/Past sections.** `upcomingRows` (not past, soonest departure first) and `pastRows` (past, most recent first, rendered at 0.5 opacity). The row now shows the date range and, on the trip `currentTrip()` picks, a "Next" badge — the widget's choice is otherwise invisible magic. A trip with no devices reads "No devices yet" instead of a blank summary line.
- **Deletion is by identity, not offset.** Chunk A's note came true immediately: with two sections, a row's offset within its own section says nothing about its index in `trips`. `deleteUpcoming(at:)`/`deletePast(at:)` map offsets through the section's own rows to a trip id, and there's a regression test that deletes Past row 0 while offset 0 of `trips` is a *different*, upcoming trip.
- **`requestsReviewForSelectedTrip` is now false on save.** A freshly created trip has no devices, so there is nothing worth asking for a review over; the prompt belongs to a completed check, not to "I typed a destination".
- **Localization**: 17 new keys added to `Localizable.xcstrings` (EN + IT) under `trips.*`/`trip.*`, and 17 dead ones removed (`trip.check.title`, `trip.check.tab.title`, `trip.check.your.trips`, `trip.check.new.title`, `trip.check.result.title`, the `next.trip.title`/`edit`/`remove`/`tip.*`/`cancel`/`save` set, and `intent.trip.check.entity.type`). ## 2026-09-10 — Saved tab slimmed, Settings added, saved-country soft lock (Chunk C)

- **`SavedCountryLimit`** (`Models/Travel Preferences/SavedCountryLimit.swift`) is the shared rule: the free tier tops out at **3** saved countries. It lives in the model layer, not in either screen, because saving happens from **two** places — the country list's swipe action and the country-detail star — and the two have to agree on when the paywall appears. `allowsToggling(code:preferences:isPremium:)` always permits **un**saving, premium or not, so a user who ends up over the limit (bought premium, saved ten, refunded) can still clear their list.
- **The premium gate moved from the tab to the action.** `SavedCountriesView` used to be locked wholesale: a non-premium user got a `ContentUnavailableView`, a blurred fake preview and a buy button, and the star in the list/detail was inert from the very first tap. Now the list is always shown, the star works for the first three, and the fourth raises the paywall. New analytics event `savedCountryLimitReached`.
- **`SavedCountriesView` is just the list**: the favorite-widget menu, `FavoriteWidgetSelectorTip`, `lockedContent` and `SavedCountriesPremiumPreview` are deleted, and `SavedCountriesViewModel` lost `isPremium`, `isPremiumPaywallPresented`, `favoriteWidgetCountry` and `selectFavoriteWidgetCountry`. It gained `freeLimitHint` ("3 of 3 saved on the free version") so a free user meets the ceiling as information rather than as a surprise.
- **`SettingsView`** — full-screen cover behind a gear in the Countries toolbar, with its own `NavigationStack` and a Done button. Sections: Travel (home country → picker, clear), Widgets (favorite country → picker, disabled with an explanatory footer when nothing is saved), Socket Buddy Premium (status, unlock, restore), About (version, rate, share), Debug (`#if DEBUG`, only when `AppDebugOverrides.isEnabled`). `SettingsViewModel.restorePurchases()` surfaces its error in an alert — a silent no-op there is indistinguishable from "you never bought it", which is exactly when a paying user needs to be told. New `AnalyticsScreen.settings`.
- **Home country is discoverable at last.** It was previously only reachable by swiping a row in the country list. Settings now has a labelled row for it.
- **`CountryDestinationPickerView` is now one picker for three jobs** — trip destination, home country, favorite-widget country — parameterised by `title`, `screen`, `allowsNoSelection` and the countries on offer. The widget picker deliberately offers only the *saved* countries, because the widget can't show one the user hasn't starred.
- **Localization**: 24 new EN+IT keys (`settings.*` and `saved.countries.free.limit`).

**A real bug this chunk introduced and then fixed — worth knowing about before touching the country list.** The lock badge on the list's star was first derived inside `CountriesListViewModel.rowModel(for:)`. That looked right and was wrong: the rows live in a `LazyVStack`, so a row already on screen is **not** rebuilt when a *different* row's save fills the last free slot — three saves later, the fourth row still showed an unlocked star (tapping it did correctly raise the paywall, so only the badge was stale). The fix is `CountriesListViewModel.canSaveMoreCountries`, passed explicitly down through `CountryResultsView` to `CountryBrowserRow` as a plain `Bool`: it is then read in the list's *own* body, which does re-run, and every row's badge updates together. `CountryBrowserRowModel` no longer carries any limit state, and `CountryBrowserRowModel.isPremium` is gone — the row asks `model.isSavedCountry || canSaveMoreCountries` instead, which also means a saved row never shows a lock. **If you add more per-row state that depends on aggregate preferences, do the same thing; do not compute it inside `rowModel(for:)`.**

**Verified on device.** Settings opens from the gear and shows the right state; the home-country row reads the real value and clears; the widget row is disabled with "Save a country first…" and becomes enabled once a country is starred; saving three countries works with a plain star, the fourth shows the lock badge *and* raises the paywall, and the Saved tab reads "3 of 3 saved on the free version". The App Group was inspected directly afterwards and holds `favorite.country.code = AL`, `home.country.code = DZ`, `next.trip.country.code = AR` with both dates and `premium.access = false` — so the widget contract is intact end to end, including Chunk A's derived trip. A cosmetic stutter was fixed in passing: the premium row no longer repeats "Socket Buddy Premium" under a section header of the same name.

**Note on a flaky UI test**: `testSavedCountries` failed once in a full run with `XCTAssertTrue failed` at `WorldPlugUITests.swift:25` — that assertion is in `setUpWithError`, i.e. the app's tab bar did not appear within 15s. It passes in isolation and the other three tests share the same setUp, so this is a launch-timeout flake (the simulator had an app instance left running from manual verification), not a defect. If it recurs outside that situation, raise the timeout rather than assuming the Saved tab is broken.
